# Review checklist

Use before marking a chapter `Completed`.

## Mandatory Depth Review (Levels 1–4)

See `DOCUMENTATION-STANDARDS.md`. Coverage of headings is not enough.

- [ ] Chapter **profile** recorded (Conceptual / Technical / Deep-dive) and appropriate
- [ ] Claimed quality level recorded (1–4) and matches profile + topic requirements
- [ ] Core language / Technical topics reach **≥ Level 3** when required; Deep-dive includes **Level 4** on critical mechanisms
- [ ] Ten-question teaching review answered “yes” for every important concept
- [ ] No tables-only / term-dump / annotation-recipe teaching for major concepts
- [ ] Examples are explained, not merely presented
- [ ] No “later chapter” substitute for a needed current explanation

## Structure and conditional sections

- [ ] Mandatory sections present; conditional sections included only when valuable
- [ ] No artificial filler sections
- [ ] Omissions recorded with reasons
- [ ] Mechanism and execution flow explained where applicable (or merge noted)
- [ ] Complex relationships illustrated with diagrams where useful
- [ ] Chapter can be understood without repeatedly consulting other chapters

## Educational quality

- [ ] Understandable for the intended audience (Track A / Track B)
- [ ] Prerequisites briefly explained in place, not only linked
- [ ] Major concepts have detailed definitions (what / why / how / when / trade-offs)
- [ ] Unfamiliar terminology and syntax explained before examples use them
- [ ] Concepts introduced here are explained now; later chapters only deepen
- [ ] Examples progressive; important lines explained; why-this-way noted when useful
- [ ] Important terms defined; glossary updated if needed
- [ ] Common misconceptions addressed
- [ ] Exercises meaningful; solutions not spoiling inline
- [ ] Solutions explain reasoning (concept, steps, output, why, alternatives)—not code-only
- [ ] Revision and Mastery present for major / Technical / Deep-dive chapters

## Continuity and progressive depth

- [ ] Chapter is independently useful as a revision resource
- [ ] Cross-links supplement rather than replace teaching
- [ ] If revisiting a prior concept, this chapter adds meaningful depth (not copy-paste)

## Technical quality

- [ ] Java claims correct for Java 21 primary path
- [ ] Version details verified against official sources (source hierarchy)
- [ ] Spec vs implementation / framework distinguished
- [ ] APIs used correctly
- [ ] Example verification status accurately labeled (Verified / Compile-verified / Illustrative)
- [ ] Verified examples actually compiled and ran; output recorded
- [ ] Edge cases considered when profile requires

## Documentation quality

- [ ] Headings consistent with template spirit; no empty filler sections
- [ ] Links valid
- [ ] References support important technical claims
- [ ] No unnecessary duplication
- [ ] `PROGRESS.md` accurate

## Practical quality

- [ ] Learner knows when to use / not use the concept
- [ ] Realistic application shown where appropriate
- [ ] Common implementation mistakes identified
- [ ] Trade-offs and limitations stated where relevant
